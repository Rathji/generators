# WEBUNTU OS — Full Build Roadmap

**Generated with the Atomic Roadmap process** (perchance.org/atomic-roadmap) · 27 Aug 2026
**Concept:** A browser desktop-operating-system simulation on Perchance — a fictional Debian-based Linux fork ("Webuntu 12 *Perch Mint*", Ubuntu/Mint-like) rendered in the **Rathji-template color scheme**, with a minimal set of working apps, full options/settings menus, a Start menu, a virtual filesystem containing **Board Games** and **Video Games** folders full of shortcuts to the `bgn-boardgame-network` and `vgn-video-game-network`, and a Software Center that links to existing Perchance generators (Rathji's projects as the **primary** source, plus other community generators).

---

## How to use this roadmap

1. Paste the entire **Kickoff prompt** block below into your AI coding agent (Perchance AI Helper, Claude Code, Cursor, Copilot, etc.).
2. The agent will initialize a `.pjs` task checklist and **hold** until you approve it, then execute **one task at a time**, marking each complete before moving on.
3. Appendices A–E are canonical reference data (game inventories, shortcut sources, design tokens) that the agent must use while building — no re-research needed.

## Kickoff prompt

```markdown
You are building **Webuntu OS** — a browser-based desktop operating-system simulation for Perchance. It is a fictional Debian-based Linux fork ("Webuntu 12, codename Perch Mint") that looks and feels like Ubuntu or Mint, but is styled entirely with the **Rathji-template color scheme** (violet #7c6cff, cyan #22d3ee, purple #8b5cf6 on a dark navy #0a0e17 surface; light theme included — see Appendix E). It ships with a minimal set of working apps, a full Settings/options system, a Start menu, a virtual filesystem with two game folders — **Board Games** (shortcuts to `bgn-boardgame-network` games) and **Video Games** (shortcuts to `vgn-video-game-network` games) — and a Software Center of shortcuts. Every shortcut/app must EITHER be a simple working in-page version OR direct to an existing/future-planned Perchance generator. Rathji's projects (perchance.org/rathjis-generators) are the primary source of external shortcuts, but NOT the only source. Focus entirely on delivering robust, modular, and testable features based on the functional requirements below.

### Workflow & Execution Rules
1. Initialize a `.pjs` file in the project root containing the structured TODO checklist of the tasks detailed below.
2. **STRICT HOLD — DO NOT START IMPLEMENTATION:** Do NOT write any implementation code, create source files, or execute any task yet. Wait until I explicitly instruct you that the backlog is complete.
3. Once I give you the signal to proceed, pick ONLY the first uncompleted task from `.pjs`.
4. Implement that single task, write corresponding validation tests, update `.pjs` to mark it complete, and stop to await review before proceeding to the next task.

### Core Framework Tasks for `.pjs`

#### Phase 1: OS Identity, Boot & Desktop Shell
1. **[x] Distro identity:** Establish Webuntu 12 "Perch Mint" as a fictional Debian-based fork (Ubuntu/Mint-like). Provide a data object holding distro name, codename, version, desktop-environment name ("Perch Desktop"), kernel flavor text, and default shell name; expose it to the About screen, boot screen, Terminal and Settings.
2. **[x] Boot sequence:** On load, show a full-screen boot screen (logo, distro name, animated progress bar, cycling pseudo-boot log lines) lasting ~2–4 seconds, then transition smoothly into the desktop. Provide a query-parameter and Settings flag to skip the boot screen.
3. **[x] Desktop root:** Render the desktop layer with the Rathji-themed wallpaper, a desktop icon grid with hover/selection states, and an auto-arrange behavior that lays icons out in a defined grid without overlap.
4. **[x] Lock / login screen:** A lightweight login screen (user profile avatar, click-to-enter) shown on first load and whenever "Lock" is chosen. It must never trap the user — a visible "Enter desktop" path is always present.
5. **[x] Design tokens:** Implement the full Rathji palette (Appendix E) as CSS custom properties used by every surface. Dark theme is the default; the light theme flips every component's colors without changing any layout.

#### Phase 2: Window Manager Core
6. **[x] Window model:** Every app or shortcut opens as a window object `{id, title, icon, w, h, x, y, minimized, maximized, closed, zIndex, content}`. The model must support an arbitrary number of simultaneously open windows.
7. **[x] Window chrome:** Each window has a title bar (icon + title + minimize/maximize/close buttons) with a distinct focused style; double-clicking the title bar toggles maximize; window content is an isolated scrollable area.
8. **[x] Dragging:** Title-bar drag moves a window; dragging is smooth, clamped to the visible desktop area, and never fires when clicking buttons.
9. **[x] Resizing:** Window edges and corners resize it with a minimum size enforced; content reflows without breaking.
10. **[x] Focus & z-order:** Clicking any part of a window brings it to front; the focused window has a distinct chrome color; z-order between multiple windows is maintained correctly.
11. **[x] Taskbar integration:** The taskbar shows one entry per open window (icon + title, active highlight). Clicking an entry toggles focus/minimize; an entry can close its window.
12. **[x] Minimize & maximize:** Minimized windows disappear from the desktop but remain in the taskbar; maximize fills the work area above the taskbar; restoring returns the prior geometry.
13. **[x] Multi-window edge cases:** New windows spawn with a cascade offset so they never stack exactly on top; windows can never end up permanently off-screen; opening an already-open app focuses it (or spawns a second instance — behavior defined per app).

#### Phase 3: Start Menu, System Bar & Menus
14. **[ ] Start menu:** A panel listing installed apps grouped by category (Accessories, Games, Internet, System, Developer, Network Hubs), with a live search filter, an "All apps" grid, a recently-launched list, and a power button.
15. **[x] System bar:** A bottom taskbar containing the Start button (Webuntu logo), a launcher area for pinned apps, a tray with a live clock (time + date), decorative network/battery icons, a volume popup with slider, and a power-menu button.
16. **[x] Power menu:** Options for Shut Down (animated shutdown screen, then reload the page), Restart (reload with boot screen), Lock (login screen), and a "Suspend" easter egg (screen dims, click to wake). Shut Down requires a confirm dialog.
17. **[x] Context menus:** Right-click menus on the desktop (arrange icons, change wallpaper, open Terminal, display settings), on the taskbar (lock, taskbar settings), and on window title bars (minimize/maximize/close). Menus dismiss on outside click and Esc.
18. **[x] Keyboard shortcuts:** Super opens the Start menu, Alt+Tab cycles windows, Ctrl+W closes the focused window, Esc closes menus. A help dialog documents all shortcuts.

#### Phase 4: Virtual Filesystem
19. **[x] Filesystem model:** An in-memory tree rooted at `/home/user` with predefined folders: **Board Games**, **Video Games**, **Documents**, **Pictures**, **Music**, **Downloads**, **Software**. Every node has `{name, type: folder|file|shortcut, icon, meta}`.
20. **[x] Path navigation:** A shared navigation service (used by File Manager, Terminal and Save dialogs) supporting path parsing, cd, parent/child lookup, and a canonical path string for every node.
21. **[x] Persistence:** The filesystem (created/renamed/deleted folders, files and shortcuts; wallpaper choice; settings) persists across reloads per user. A "Reset desktop" option restores defaults. If storage is unavailable, fall back to in-memory without erroring.
22. **[x] Shortcut nodes:** Folders can contain `.desktop`-style shortcut nodes carrying `{name, icon, color, type: app|game|link|stub, target}`. Shortcuts render as icons in the File Manager and on the desktop; double-click launches them.

#### Phase 5: Settings & Options Menus
23. **[x] Control Center app:** A windowed Settings app with sections: Appearance (theme, accent, text size, reduce motion, wallpaper), Personalization (desktop icons toggle, taskbar position), Sound (UI sounds toggle), System (About, Reset, storage note). Every option applies instantly and persists.
24. **[x] Theme engine:** Rathji palette is selectable — dark/light theme plus the 5 preset accent swatches and a custom-hex option — applied live across all windows, taskbar, menus and apps, then persisted.
25. **[x] Wallpaper picker:** Several built-in Rathji-themed wallpapers (gradient, radial glow, grid pattern, network-hub art) selectable from Settings and the desktop context menu; a custom-image option accepts a pasted image URL.
26. **[x] Accessibility:** Reduce-motion disables all animations/transitions; text-size scales S/M/L; focus outlines are always visible; every menu is keyboard-operable.
27. **[x] UI sounds:** Subtle optional UI sounds (open, close, error, startup chime) synthesized with WebAudio (no external assets). Off by default; only ever plays after a user interaction (autoplay policy).

#### Phase 6: Standard Apps (Simple Working In-Page Versions)
28. **[x] File Manager:** Navigates the virtual filesystem with breadcrumbs, back/forward/up, grid and list views, create/rename/delete for folders and files, and launches shortcut nodes. Includes empty-state and error states.
29. **[x] Text Editor:** Opens/creates/saves plain-text files in the virtual FS; supports multi-line editing, undo/redo, line/column counter, word count, in-file search, and an unsaved-changes guard on close.
30. **[x] Calculator:** Basic scientific calculator (+,−,×,÷,%,√,±, memory, keyboard input) with a live display and correct divide-by-zero handling.
31. **[x] Terminal:** A fictional "Perch shell" with working commands — ls, cd, pwd, cat, mkdir, rm, touch, echo, clear, help, an `about-webuntu` neofetch-style command, and `open <name>` to launch apps/shortcuts — all operating on the real virtual FS. History (↑/↓) and Tab autocomplete.
32. **[x] Image Viewer:** Opens images (wallpapers and arbitrary image URLs) with fit/zoom/pan and prev/next when multiple images are available; graceful error on unloadable images.
33. **[x] Music Player:** Plays a small built-in set of WebAudio synth loops (no external files) with play/pause/next/volume and a playlist UI; an option to add a custom audio URL; respects the global sound toggle.
34. **[x] Browser app:** An address-bar "web browser" that navigates the OS to any Perchance generator URL — rendering the target in an embedded window (via the null-perchance embed URL) with Back/Forward/Reload/Home and an always-available "Open in new tab" fallback.
35. **[x] Notes app:** Per-user notes stored in the virtual FS under Documents/Notes with create/edit/delete, titles and timestamps.
36. **[x] System Monitor:** A fake-but-live monitor showing animated CPU/RAM/network meters, open-window count, and uptime; animates smoothly at 60fps even with many windows open.

#### Phase 7: Board Games Folder (bgn-boardgame-network)
37. **[x] Board Games folder:** Ships with the BGN hub shortcut plus curated shortcuts to live BGN games (Appendix A), each showing icon, title, genre chip and player count from BGN data. Games grouped into subfolders by genre (Strategy, Card, Word & Pen & Paper, RPG, Reference & Tools).
38. **[x] Game launcher:** Double-clicking a game shortcut opens a "Game Window" that embeds the generator via the null-perchance embed URL, with a toolbar (Reload, Open in new tab, Close). If the embed fails or the target is coming-soon, a friendly dialog offers the direct top-level link and a "Back to games" action.
39. **[x] BGN hub shortcut:** A pinned "The Boardgame Network" shortcut that opens the hub inside the Browser window (embed) with an Open-in-new-tab fallback.
40. **[x] Coming-soon handling:** Shortcuts flagged `comingSoon` render with a "Soon" badge and are disabled with an explanatory tooltip; the launch dialog offers "Visit the hub instead".

#### Phase 8: Video Games Folder (vgn-video-game-network)
41. **[x] Video Games folder:** Ships with the VGN hub shortcut plus curated shortcuts to VGN games (Appendix B) with arcade-styled icons carrying era/genre/year data from the VGN hub, grouped into subfolders by era (Network, Arcade, 8-Bit, Early 3D).
42. **[x] VGN game launch:** The same game launcher as Phase 7 with arcade-styled window chrome, including the Open-in-new-tab fallback to the top-level page.
43. **[x] VGN hub shortcut:** A pinned "The Video Game Network" hub shortcut (embed + Open-in-new-tab fallback).
44. **[x] Developer templates subfolder:** A "Software" → "Developer" folder with link-shortcuts to VGN and BGN game templates (Appendix C) — clearly labelled as tools for making games, not games themselves.

#### Phase 9: Software Center & External Shortcuts (Rathji as Primary Source)
45. **[x] Software Center app:** A windowed catalog listing "Installed" (preinstalled apps) and "Available" (external generator shortcuts) grouped by category (Tools, AI & Images, Games & RPG, Audio & Music, Developer, Community Hubs). Each entry shows name, icon, source tag (Rathji / BGN / VGN / Community), one-line blurb, and an Install/Open/Visit action.
46. **[x] Rathji tool shortcuts (primary source):** Shortcuts to Rathji's existing generators: Perchance Archive Search, VS Code Web, Easy Upload, File Format Converter, GENESIS, Flux Reification Engine, VoxelCraft, Image Matrix, D&D Character Forge, D&D 5E Rules & Stats, Battle Map Forge, GM Battle Manager, Falling Notes Piano, AI Voice Assistant, Atomic Roadmap (Appendix C). All launch via embed-with-new-tab-fallback.
47. **[x] Community shortcuts (secondary sources):** A small set of non-Rathji generators — official plugin pages (ai-text-plugin, text-to-image-plugin, the plugins directory) and well-known community tools (Appendix D). At build time, verify each slug is live via the perchance API or Archive Search; mark any dead slug as coming-soon rather than shipping a broken link.
48. **[x] Future-planned stubs:** A defined set of "planned" apps (e.g., Weather, Mail client, Minesweeper, PDF Viewer) present in the Software Center as Coming Soon / "In development" — browsable but not launchable, reinforcing the fictional-OS feel.

#### Phase 10: Polish, QA & Delivery
49. **[x] Responsive layout:** Verify the OS at phone (390×844), tablet and desktop widths — taskbar repositions to the bottom on small screens and remains usable, windows open fully visible, text scales, and nothing overflows.
50. **[x] Robustness:** Opening many windows, missing shortcut targets, rapid open/close, and storage-unavailable must never freeze or crash the page; the browser console is error-free.
51. **[x] Meta:** `$meta` with title, description, tags, header mode minimal, and an image (a screenshot of the desktop) suitable for a social card.
52. **[x] Final visual QA:** Compare the rendered desktop against the Rathji palette intent (Appendix E) — verify dark and light themes, every app window, both game folders, Start menu, Settings, Software Center, and the boot/shutdown screens in a vision-based pass.
```

## Appendix F — Launch mechanics (shortcut behavior)

- **Embed (in-OS window):** `<iframe src="https://null.perchance.org/<slug>">` — the platform auto-redirects the special `null` host to the target generator's real subdomain, so any Perchance generator can be embedded this way. Used by the game launcher, Browser app and hub shortcuts.
- **Open in new tab (always available fallback):** link to `https://perchance.org/<slug>` — the top-level page, always navigable/shareable. Every game window's toolbar exposes this.
- **Coming-soon / dead targets:** never ship a broken link — render disabled with a "Soon" badge, or a friendly dialog offering the hub instead.

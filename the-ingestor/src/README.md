# The Ingestor

Perchance generator that ingests diverse content sources (Perchance generators, websites, raw text, PDFs) and transforms them into structured analysis via five processing modes (Featurize, Ingestify, Ask, Extract, Glossary).

- Phase 2 (Data Acquisition) fully complete: Perchance Source Resolver (6), Web Content Scraper (7), PDF Text Extractor (8), Textarea Input Handler (9).

- Phase 4 (Analysis Mode Logic) fully complete: Featurize (13), Ingestify (14), Ask (15), Extract (16), Glossary (17) engines all done — every mode's prompt logic exists and is wired to `generateText`.
- Phase 5 (UX & Polish) fully complete: Progress Visualization (18), Output Streaming (19), Final Integration Test (20).
- The "Fetch Source"/"Capture Text" button in the Source zone ingests the selected source into a shared `ingestState` context blob, and a context-monitor line reports chars/tokens/budget + chunk count. When the blob exceeds the chunk budget, a "🧠 Summarize" button appears and runs the recursive summarization loop (real `generateText` calls) to compress it into a single context digest (stored on `ingestState.summary`). **Run Analysis is now LIVE**: it auto-summarizes an over-budget context, drives the progress bar (Task 18) through the summarizer, then runs the selected mode engine and streams the markdown output (Task 19) into the right panel with a blinking caret, finishing with the Rendered stat so exports (Task 5) can download it.

## Architecture
- `main.pjs` — roadmap TODO checklist at top (source of truth: `scratch/message-attachments/ingestor-atomic-roadmap.md`), `$meta`, the `superFetch = {import:super-fetch-plugin}` import (Task 7), `generateText = {import:ai-text-plugin}` (Tasks 12–14), and vendored rathji-template components (`rathjiTemplate`/`rathjiCard` — no import needed).
- `index.html` — dark, responsive two-panel app shell built on the rathji-template design system (CSS vars, settings panel with theme/accent/size/motion, toasts). Left panel: Input & Configuration — tabbed source selector (Perchance URL / Website URL / Textarea / PDF Upload) with per-source inputs + live status summary (Task 2), a Fetch Source button + ingest status line (Tasks 6–8; hidden on the Textarea tab — Task 9), mode selector (Task 3: 5 selectable mode chips defined in the `MODES` array, per-mode description readout, Ask-mode query input that appears only when Ask is selected; prompt logic is Tasks 13–17). Right panel: Output & Results — empty state with a "Preview the renderer" sample button; markdown renderer (`mdToHtml`, Task 4) exposed as `window.IngestorOutput` (`render`/`stream`/`clear`/`demo`); streaming coalesces via `setTimeout` (NOT rAF — rAF can stop firing in this environment); export bar (Task 5) exposed as `window.IngestorExport` (`build`/`download`) — .md/.txt raw, .json metadata wrapper, .csv table extraction with fallback.
- **Ingesters (Tasks 6–9)** exposed as `window.Ingestors`: `parsePerchanceName`/`extractImports`/`resolvePerchance` (Perchance API — `getGeneratorsAndDependencies`, plain fetch with superFetch fallback, recursive import resolution with SOURCE headers), `scrapeWeb`/`ingestWeb` (DOMParser + skip-tag/boilerplate filtering, superFetch transport), `extractPdfText`/`loadPdfjs` (pdf.js 3.11.174 from jsdelivr, worker as same-origin blob URL, page-by-page reading-order extraction), `ingestTextarea` (verbatim capture). All write to the shared `ingestState = {type, label, text, meta, error, status}`.
- **Context & chunking (Tasks 10–11):** `window.ContextMonitor` (`measure` → {characters, words, tokens, limit, pct, remaining, over}, chars/4 token heuristic, default 8000-token window, `setLimit`), `window.Chunker` (`chunk` → sequential overlapping chunks bounded by chunkTokens/overlapTokens, line-boundary breaks, fenced code kept whole). A `#ctxMonitor` readout under the source zone shows budget usage and goes amber with a chunk count when over.
- **Recursive Summarization Loop (Task 12):** `window.Summarizer.run(text, opts)` chunks the input, writes a terse budget-constrained note per chunk (`buildChunkNotePrompt`), then recursively collapses groups of notes (`buildGroupPrompt`, groupSize default 8) until ONE consolidated context digest remains — genuinely recursive for arbitrary sizes. Prefix-cache-friendly prompts (fixed preamble → content → TASK at the end). `opts.generate` injects a fake generator for tests; `opts.onProgress({phase:'chunk'|'group', level, index, total})` feeds the UI status line (Task 18 will visualize). `cancel()` stops in-flight generation. Driven by the "🧠 Summarize" button (visible when the blob exceeds the chunk budget); the digest lands on `ingestState.summary` and the context monitor shows "🧠 digest ready".
- **Mode engines (Tasks 13–17):** all five engines expose `buildPrompt(context, opts)` / `.run()` and use `generateText` via `opts.generate`-injectable runs, wired into the pipeline in Task 20.
  - `window.Featurize` (13) — categorized, exhaustive feature inventory prompt (H2 category headings, nothing invented, GitHub-flavored markdown).
  - `window.Ingestify` (14) — digest prompt demanding exactly eight H2 sections (One-liner, Overview, Capabilities, Details, Key Facts table, Strengths, Limitations, Bottom line).
  - `window.Ask` (15) — `buildPrompt(context, query, opts)` answers a specific query using ONLY the context (admits when the context lacks the answer).
  - `window.Extract` (16) — five H2 categories: Entities, APIs & Functions, Code Snippets, Config Options, Data Points ("None found." for empty categories).
  - `window.Glossary` (17) — alphabetized | Term | Definition | Notes | table of context terms with plain-English definitions.
- **Phase 5 pipeline (Tasks 18–20):**
  - `window.Progress` (18) — `show(label,{fraction})` / `set(fraction,label)` / `pulse(label)` / `hide()` / `visible()` / `label()` / `fillPct()`; determinate bar (CSS width transition) or indeterminate pulse; driven by the summarizer's `onProgress` and the analyzer pulse.
  - `window.Analyzer` (19) — `run({mode, context?, generate?, timeoutMs?, onChunk})` / `cancel()` / `isRunning()` / `modes`. All five engines forward `onChunk` + expose `onStart(promise)` for cancellation; `Analyzer.run` streams chunks and returns `{text, mode, streamed, chunks, ms, contextChars}`.
  - `window.__INGESTOR__.pipeline()` (20) — `run()` is the live `runAnalysis` flow wired to the Run Analysis button: guard (ingested context + Ask query), auto-summarize over-budget context with progress bar, run the mode engine with streaming into `IngestorOutput`, finish with Rendered stat so `IngestorExport` can download the buffer.
- `scratch/tests/task1.test.js` … `task20.test.js` — validation checks (run via page_eval); task20 also drives the full UI flow end-to-end with a stubbed `root.generateText`.

## Build notes
- rathji-template source fetched from `perchance.org/rathji-template` (vendor reference: `scratch/generators/rathji-template/`). To update vendored components, re-fetch and diff.
- pdf.js pinned to `pdfjs-dist@3.11.174` (jsdelivr UMD + worker). The worker must be a same-origin blob URL — cross-origin workers are blocked by the web platform.
- Design tokens live in `:root` in index.html; light theme via `html.light`; accents are runtime-swappable.

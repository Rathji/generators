The BGN standard — what this tool checks for

Every network generator is graded against the same checklist the flagship games follow. Required items are worth 3 points each, recommended items 1 point; a missing required item drops the grade to at most C. Tool and Reference pages (genre Tool or Reference — reference templates like bgn-reference-template count as tools) are graded to their own standard: game-specific items — online play, the fullscreen board, turn order & teams, chat/lounge/audio, the card-deck plugin — are marked n/a, while the shared standards still apply (meta, design system, layout basics, no secrets, hub footer). Tools are additionally held to the self-check Audit link; reference pages get it waived. Every generator must declare its genre in $meta — matching the category used on the hub shelf; it's the flag that decides which standards apply.

List structure (main.pjs) — balanced \[ \] / \{ \} brackets, no lines starting with a bracket, 2-space indentation, and the config block:

$meta
  title = Game Title
  description = ...
  tags = ...
  image = https://user.uploads.dev/file/....
  genre = Strategy   ← required, must match the hub shelf (Strategy, Cards, Tool, Reference, …)

hubUrl = https://perchance.org/bgn-boardgame-network
gameTitle = ...   gameTagline = ...   gameKicker = ...   gameGenre = ...
gamePlayers = ...   accentColor = ...   heroImage = ...
createServerSocket = \{import:server-plugin\}

CSS & design — the shared BGN design system stylesheet, a body\{text-align:left\} override (Perchance centre-aligns content otherwise), and a viewport meta:

<link rel="stylesheet" href="https://user.uploads.dev/file/67107d8c89844a7378e599e5110c369f.css">
<meta name="viewport" content="width=device-width, initial-scale=1">

HTML & layout — a lobby with mode cards (data-mode="local" hotseat + data-mode="online"), an online panel (createRoomBtn, joinCodeInput), the game table (.bgn-table, .bgn-board), a room box (roomCodeEl, copyCodeBtn, leaveBtn), turn indicator, game log, action buttons (newGameBtn/claimBtn/menuBtn), help overlay, and the footer with a link back to the hub. No duplicate element ids.

Online features — an authoritative <script type="text/x-server-plugin"> with durable state slots, room codes and snapshot broadcasting; a client connectSocket wired to it; plus the shared network extras: BGN audio (window.BGN_AUDIO, starting muted), the Lounge, in-game chat, save/continue, the share/export toolkit, and the self-check footer link (Audit — a popup that embeds the standards checker pre-loaded with the game's own name).

Turn order & teams — every multiplayer game (2+ players) gets the 🎲 panel, openable from the lobby and the in-table side panel: a who-goes-first roller that drives the real turn order (game.first locally/AI, a setFirst rpc online, createRoom honoring a lobby roll), a team splitter and a seat draw rendered on the player cards with a 🎯 starts marker on the starting player — all persisting through save/continue/share-import. Single-player games are exempt.

Fullscreen board — a ⛶ Full screen button (hidden until the board registers) top-right of the board area, and a full-window overlay that maximises the playing area. Opening moves the live canvas, pass button, tile-in-hand and meeple chooser into the overlay (never clones) and restores them to their exact original spots on close (✕ or Escape). Exposes window.bgnFullscreen.register(\{canvas, tile, meeple, resize\}), .open(), .close(), .isOpen().

Game assets — games that play with a standard deck of cards (poker, blackjack, bridge, solitaire, …) must import the shared card-deck-plugin and render through it, so the whole network uses one deck:

cardDeck = \{import:card-deck-plugin\}
cardEl.innerHTML = cardDeck("AS");   // cardDeck("10C"), cardDeck("back"), …

These checks are flagged n/a for games that don't use a standard deck, and waived for reference/tool pages.

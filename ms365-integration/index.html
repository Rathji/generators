🧩 Microsoft 365 Integration

A Perchance plugin that plugs your generators into Microsoft 365 — Outlook mail, OneDrive/SharePoint, Calendar, and To Do — through the Microsoft Graph API.

Live playground

Try the whole pipeline right here. Enter your Azure app's Client ID, then press Sign in with Microsoft — a popup opens at the Microsoft Identity Platform and the returned authorization code is exchanged for access + refresh tokens (via super-fetch-plugin, since the token endpoint is not CORS-enabled). Tokens are persisted in this generator's own origin partition and auto-refresh before they expire — reload the page and you stay signed in. Once signed in you can Validate tenant (confirms your account belongs to a genuine Microsoft 365 tenant; deep /organization verification runs automatically when Organization.Read.All is granted), Test connection (pings /me and measures the full auth + API pipeline end-to-end), or use the Graph request box to call any Graph endpoint straight from the page — headers, JSON, and 429/503 backoff are handled by the wrapper. Feature modules (mail, files, calendar, tasks) are exposed on window.ms365 for programmatic use.

How it works

Everything is a small ES module under src/, imported by this page's module script and exposed as window.ms365. At a high level the pipeline is:

  • OAuth2 authorization-code + PKCE (src/auth/oauth2.js) — configure() sets your clientId/tenant/scopes; launchAuthFlow() opens a popup at the Microsoft Identity Platform v2.0 authorize endpoint carrying a per-request PKCE code challenge and anti-CSRF state; the popup redirects back to this page's URL and handleCallback() exchanges the code for tokens. Because the token endpoint rejects browser CORS, the exchange (and every later refresh) goes through super-fetch-plugin.
  • Token lifecycle (src/auth/token-store.js + oauth2.js) — tokens are persisted as JSON in this origin's localStorage. getValidToken() returns the access token, single-flight-refreshing it when it is near expiry; scheduleAutoRefresh() keeps an in-page timer so it stays fresh; onSessionChange()/onSessionExpired() notify your UI.
  • Graph request wrapper (src/graph/graph-client.js) — graphRequest(method, path, opts) attaches the bearer token, builds OData query strings with literal $ keys (URLSearchParams would encode $ and break Graph), parses JSON, retries 429/503/504 with exponential backoff honoring Retry-After, refreshes-and-retries once on 401, and follows @odata.nextLink pages via getAllPages().
  • Error mapping (src/graph/error-mapper.js) — every Graph failure is normalized to an Error carrying \{code, status, category, friendly, hint, retryable\}, so your app can branch on err.code and show err.friendly to users.
  • Scoped permissions (src/auth/scoped-permissions.js) — ensureScopes("mail") checks the current grant and, if a scope is missing, triggers incremental-consent auth asking only for the missing scopes, then merges them into the active config. The user stays signed in — no full re-consent.
  • Feature modules (src/mail, src/files, src/tasks, src/health) — thin, opinionated wrappers that map friendly options to Graph endpoints and normalize every response to a standard internal shape.

Set it up in Azure

  • Register an app at aka.ms/aadappreg (or Entra admin center → App registrations).
  • In Authentication → Platform configurations → Single-page application, add this exact Redirect URI (shown live in the widget): …. No client secret needed — this is a public client using PKCE.
  • In API permissions, grant User.Read (default) plus whatever features you plan to use: Mail.ReadWrite, Calendars.ReadWrite, Files.ReadWrite.All, Tasks.ReadWrite. The scoped-permission requestor asks for these on demand at sign-in, but the app registration must still pre-authorize them; deep tenant validation additionally needs Organization.Read.All (admin consent).
  • Paste the Application (client) ID into the widget (or ms365Config.clientId in main.pjs).

Use it in your own generator

Import this generator as a plugin, set your app's Client ID, then render the widget or call the API directly. Everything is reachable on window.ms365.

// main.pjs of your generator
ms365 = \{import:ms365-integration\}
ms365Config
  clientId = 01234567-89ab-cdef-0123-456789abcdef
  tenant = common
  scopes
    openid
    profile
    email
    offline_access
    User.Read

Then render the auth widget anywhere in your HTML with \[ms365\], or configure at runtime from a script: root.ms365.oauth2.configure(\{ clientId: "01234567-89ab-...", tenant: "common" \}).

Programmatic API

Every call returns a Promise. launchAuthFlow() opens the popup and resolves with \{status, tokens, profile\} on success (or null when the browser redirects the page instead of using a popup):

const res = await root.ms365.oauth2.launchAuthFlow();   // sign in
const token = await root.ms365.oauth2.getValidToken();  // auto-refreshed

// Graph core — any endpoint, paging included
const me = await root.ms365.graph.graphGet("/me",
  \{ query: \{ $select: "id,displayName,mail" \} \});
const msgs = await root.ms365.graph.getAllPages("/me/messages",
  \{ query: \{ $top: 50 \} \});

// Mail
const inbox = await root.ms365.mail.query.listInbox(\{ top: 10 \});
const found = await root.ms365.mail.query.searchEmails(\{
  from: "boss@corp.com", keyword: "report",
  receivedAfter: new Date(Date.now() - 7 * 864e5),
\});
await root.ms365.mail.send.sendEmail(\{
  to: "jane@corp.com", subject: "Hello", body: "Hi Jane",
  html: "<p>Hi Jane</p>", importance: "high",
\});

// Calendar
const upcoming = await root.ms365.mail.calendar.listUpcomingEvents(\{
  start: new Date(), end: new Date(Date.now() + 7 * 864e5),
\});
await root.ms365.mail.calendar.createEvent(\{
  subject: "Demo", start: new Date(), end: new Date(Date.now() + 3600e3),
  attendees: ["jane@corp.com"], location: "Room 1",
\});

// Files (OneDrive)
const files = await root.ms365.files.discover.listFiles(\{ top: 20 \});
const uploaded = await root.ms365.files.transfer.uploadFile(\{
  name: "report.pdf", data: blob, mimeType: "application/pdf",
  conflictBehavior: "replace",
\});
const dl = await root.ms365.files.transfer.downloadFile(\{ itemId: uploaded.id \});
const access = await root.ms365.files.auditor.checkAccess(\{ itemId: uploaded.id \});

// To Do tasks
const lists = await root.ms365.tasks.sync.listTaskLists();
const open = await root.ms365.tasks.sync.listTasks(\{
  listId: lists.value[0].id, includeCompleted: false,
\});
await root.ms365.tasks.update.setTaskComplete(\{
  listId: lists.value[0].id, taskId: open.value[0].id,
\});
await root.ms365.tasks.update.setTaskDueDate(\{
  listId: lists.value[0].id, taskId: open.value[0].id,
  dueDateTime: new Date(),
\});

// Health + on-demand scopes
const health = await root.ms365.health.testConnection();
// health = \{ ok, latencyMs, tokenStatus, user, error \}
await root.ms365.scopedPermissions.ensureScopes("mailSend");

Errors: every Graph call routes through the error mapper, so catch the promise and read err.code/err.status to branch, or show err.friendly (a human-readable message) directly to the user.

API reference

Everything lives under src/ as ES modules (auth → oauth2.js/token-store.js/tenant-validator.js/scoped-permissions.js; Graph → graph-client.js/error-mapper.js; mail → mailbox-query.js/email-dispatcher.js/calendar-sync.js; files → file-discovery.js/file-transfer.js/permission-auditor.js; tasks → task-sync.js/task-updater.js; health → connection-check.js) and are exposed as window.ms365. To render the auth widget from a script: outputEl.innerHTML = root.ms365(); — the widget's hydration, saved-config restore, callback handling and lifecycle listeners are all wired up by this page's module script.

Key functions: oauth2.configure()/launchAuthFlow()/handleCallback()/getValidToken() (auto-refresh) · tenantValidator.validateTenant() · graph.graphRequest()/graphGet()/graphPost()/graphPatch()/graphDelete()/getAllPages() · errorMapper.mapGraphError()/formatFriendlyError() · mail.query.searchEmails()/mail.query.listInbox() · mail.send.sendEmail()/createDraft() · mail.calendar.listUpcomingEvents()/createEvent() · files.discover.listFiles()/searchFiles() · files.transfer.uploadFile()/downloadFile() · files.auditor.checkAccess() · tasks.sync.listTasks() · tasks.update.updateTask() · health.testConnection()/assertConnected() · scopedPermissions.ensureScopes().

🧩 Microsoft 365 Integration

A Perchance plugin that plugs your generators into Microsoft 365 — Outlook mail, OneDrive/SharePoint, Calendar, and To Do — through the Microsoft Graph API.

OAuth2 + PKCE sign-in Token auto-refresh Tenant validation Graph API wrapper Error mapping Mail & calendar Files & permissions To Do tasks Health checks

Live playground

Try the whole pipeline right here. Enter your Azure app's Client ID, then press Sign in with Microsoft — a popup opens at the Microsoft Identity Platform and the returned authorization code is exchanged for access + refresh tokens (via super-fetch-plugin, since the token endpoint is not CORS-enabled). Tokens are persisted in this generator's own origin partition and auto-refresh before they expire — reload the page and you stay signed in. Once signed in you can Validate tenant (confirms your account belongs to a genuine Microsoft 365 tenant; deep /organization verification runs automatically when Organization.Read.All is granted), Test connection (pings /me and measures the full auth + API pipeline end-to-end), or use the Graph request box to call any Graph endpoint straight from the page — headers, JSON, and 429/503 backoff are handled by the wrapper. The whole API — auth, Graph, mail, files, calendar, tasks, health — is reachable as root.ms365 in your own generator, and on this page as root.getMs365Api(); see the API reference below.

How it works

The entire implementation lives in main.pjs as Perchance-js functions (name(args) => \{ … \}) — no ES modules, no import/export. That matters because a Perchance \{import:x\} pulls in only x's main.pjs: it never runs x's index.html or its src/ files. So the API is assembled once, cached in a single lazily-created store (window.__ms365Internal), and returned from $output — importing this generator gives you the whole API as root.ms365, with no widget, no extra scripts and no HTML required. The src/ files are this page's own playground wiring plus the mock-free validation suites; each module there is a thin shim that delegates to the same main.pjs functions. At a high level the pipeline is:

  • OAuth2 authorization-code + PKCE (main.pjs §6) — configure() sets your clientId/tenant/scopes; launchAuthFlow() opens a popup at the Microsoft Identity Platform v2.0 authorize endpoint carrying a per-request PKCE code challenge and anti-CSRF state; the popup redirects back and handleCallback() exchanges the code for tokens. Because the token endpoint rejects browser CORS, the exchange (and every later refresh) goes through super-fetch-plugin.
  • Token lifecycle (§4–5) — tokens are persisted as JSON in this origin's localStorage by default, and getValidToken() returns the access token, single-flight-refreshing it when it is near expiry; scheduleAutoRefresh() keeps an in-page timer so it stays fresh; onSessionChange()/onSessionExpired() notify your UI. Storage is injectable and may be async (a caller can back tokens with kv-plugin/IndexedDB), and every key is namespaced by the connection (ms365.oauth2.session::<clientId>|<tenant>) so multiple configs never collide.
  • Graph request wrapper (§9) — graphRequest(method, path, opts) attaches the bearer token, builds OData query strings with literal $ keys (URLSearchParams would encode $ and break Graph), parses JSON, retries 429/503/504 with exponential backoff honoring Retry-After, refreshes-and-retries once on 401, and follows @odata.nextLink pages via getAllPages().
  • Error mapping (§7) — every Graph failure is normalized to an Error carrying \{code, status, category, friendly, hint, retryable\}, so your app can branch on err.code and show err.friendly to users.
  • Scoped permissions (§11) — ensureScopes("mail") checks the current grant and, if a scope is missing, triggers incremental-consent auth asking only for the missing scopes, then merges them into the active config. The user stays signed in — no full re-consent.
  • Feature namespaces (§12–15) — thin, opinionated wrappers (mail, files, tasks, health) that map friendly options to Graph endpoints and normalize every response to a standard internal shape.

Relay mode (§6) lets importers share a single Azure redirect URI: set relay: true (or a page name) in your config, register https://perchance.org/ms365-integration as the app's redirect URI, and this plugin's own page — loaded with ?code=…&state=…&__ms365_relay=1 — postMessages the authorization response back to the opener and closes itself. launchAuthFlow() accepts that relay message as well as the same-origin popup message, so forks and importers never have to register their own <publicId>.perchance.org/<name> origin.

Set it up in Azure

  • Register an app at aka.ms/aadappreg (or Entra admin center → App registrations). Leave it a public client — PKCE only, no client secret anywhere.
  • In Authentication → Platform configurations, add your Redirect URI. For this page (and for the shared relay redirect) use the Single-page application platform and register https://perchance.org/ms365-integration — one URI that every importer and fork can share, because this page relays the authorization code back to the opener (?__ms365_relay=1). The widget shows the URI it will use live, so you can copy it: …. If you instead want each generator to come back to its own page, register that page's URI under the Web platform too (older apps may still call it "Web"); the plugin uses whatever redirectUri you configure.
  • In API permissions, grant User.Read (default) plus whatever features you plan to use: Mail.ReadWrite, Calendars.ReadWrite, Files.ReadWrite.All, Tasks.ReadWrite. The scoped-permission requestor asks for these on demand at sign-in (incremental consent — the user stays signed in), but the app registration must still pre-authorize them; deep tenant validation additionally needs Organization.Read.All (admin consent).
  • Paste the Application (client) ID into the widget (or set it via root.ms365.configure(\{ clientId: … \}) / ms365Config.clientId in main.pjs).

Use it in your own generator

Import this generator as a plugin and the whole API is available as root.ms365 — auth, Graph, mail, files, calendar, tasks, health, scoped permissions. No widget, no extra scripts, no HTML required: a Perchance import pulls in this generator's main.pjs only, and main.pjs is the implementation.

main.pjs
// main.pjs of your generator
ms365 = \{import:ms365-integration\}

// Optional starter defaults (tweak these in your generator settings):
ms365Config
  clientId = 01234567-89ab-cdef-0123-456789abcdef
  tenant = common
  scopes
    openid
    profile
    email
    offline_access
    User.Read

Then configure at runtime from any script (importers can't edit the plugin's pjs lists, so configure() is the supported way to set things at run time) and call the API:

index.html
await root.ms365.configure(\{
  clientId: "01234567-89ab-cdef-0123-456789abcdef",
  tenant: "common",                 // or a tenant id / "organizations"
  relay: true,                      // share this plugin's page as the redirect URI
  // scopes, redirectUri, prompt, storage, fetchImpl are all optional
\});
const me = await root.ms365.graph.graphGet("/me");

If you want the same auth card this page shows, render \[ms365\] (or \[ms365.widget()\]) in your HTML — it's plain markup; wire your own buttons to launchAuthFlow()/handleCallback(), or copy this page's hydration script as a starting point.

Consume from another generator

A complete consumer — no plugin HTML, no window.ms365, no extra script tags. Drop this in your own <script type="module"> (or a file under your src/):

index.html
// index.html (or src/ms365-consumer.js) of YOUR generator
const ms365 = root.ms365;                 // the imported plugin's API

await ms365.configure(\{
  clientId: "01234567-89ab-cdef-0123-456789abcdef",
  tenant: "common",
  relay: true,                            // one shared Azure redirect URI
  scopes: ["openid", "profile", "email", "offline_access",
           "User.Read", "Mail.Read"],
\});
await ms365.auth.handleCallback();        // no-op unless this load has ?code
try \{
  const me = await ms365.graph.graphGet("/me",
    \{ query: \{ $select: "id,displayName,mail" \} \});
  const inbox = await ms365.mail.query.listInbox(\{ top: 5 \});
  console.log(me.displayName, inbox.value.length, "messages");
\} catch (err) \{
  if (err.code === "not_authenticated") ms365.auth.launchAuthFlow();
  else console.warn(err.code, err.friendly);
\}

Back tokens with your own async store (e.g. kv-plugin) instead of localStorage by passing a storage whose getItem/setItem/removeItem may return promises — the plugin awaits thenables and namespaces every key by connection.

Programmatic API

Every call returns a Promise. launchAuthFlow() opens the popup and resolves with \{status, tokens, profile\} on success (or null when the browser redirects the page instead of using a popup):

index.html
const res = await root.ms365.oauth2.launchAuthFlow();   // sign in
const token = await root.ms365.oauth2.getValidToken();  // auto-refreshed

// Graph core — any endpoint, paging included
const me = await root.ms365.graph.graphGet("/me",
  \{ query: \{ $select: "id,displayName,mail" \} \});
const msgs = await root.ms365.graph.getAllPages("/me/messages",
  \{ query: \{ $top: 50 \} \});

// Mail
const inbox = await root.ms365.mail.query.listInbox(\{ top: 10 \});
const found = await root.ms365.mail.query.searchEmails(\{
  from: "boss@corp.com", keyword: "report",
  receivedAfter: new Date(Date.now() - 7 * 864e5),
\});
await root.ms365.mail.send.sendEmail(\{
  to: "jane@corp.com", subject: "Hello", body: "Hi Jane",
  html: "<p>Hi Jane</p>", importance: "high",
\});

// Calendar
const upcoming = await root.ms365.mail.calendar.listUpcomingEvents(\{
  start: new Date(), end: new Date(Date.now() + 7 * 864e5),
\});
await root.ms365.mail.calendar.createEvent(\{
  subject: "Demo", start: new Date(), end: new Date(Date.now() + 3600e3),
  attendees: ["jane@corp.com"], location: "Room 1",
\});

// Files (OneDrive)
const files = await root.ms365.files.discover.listFiles(\{ top: 20 \});
const uploaded = await root.ms365.files.transfer.uploadFile(\{
  name: "report.pdf", data: blob, mimeType: "application/pdf",
  conflictBehavior: "replace",
\});
const dl = await root.ms365.files.transfer.downloadFile(\{ itemId: uploaded.id \});
const access = await root.ms365.files.auditor.checkAccess(\{ itemId: uploaded.id \});

// To Do tasks
const lists = await root.ms365.tasks.sync.listTaskLists();
const open = await root.ms365.tasks.sync.listTasks(\{
  listId: lists.value[0].id, includeCompleted: false,
\});
await root.ms365.tasks.update.setTaskComplete(\{
  listId: lists.value[0].id, taskId: open.value[0].id,
\});
await root.ms365.tasks.update.setTaskDueDate(\{
  listId: lists.value[0].id, taskId: open.value[0].id,
  dueDateTime: new Date(),
\});

// Health + on-demand scopes
const health = await root.ms365.health.testConnection();
// health = \{ ok, latencyMs, tokenStatus, user, error \}
await root.ms365.scopedPermissions.ensureScopes("mailSend");

// Introspection + teardown
root.ms365.version;                        // "2.0.0"
root.ms365.capabilities();                 // \{ version, namespaces, features, featureScopes \}
await root.ms365.reset();                  // clears config, session, pending, timers, popups

Errors: every Graph call routes through the error mapper, so catch the promise and read err.code/err.status to branch, or show err.friendly (a human-readable message) directly to the user.

API reference

Everything is implemented in main.pjs (sections: 1 config · 2 internal state · 4–5 storage & token store · 6 OAuth2 + PKCE + relay · 7 error mapper · 8 OData · 9 Graph wrapper · 10 tenant validator · 11 scoped permissions · 12 mail · 13 files · 14 tasks · 15 health · 16 widget · 19 namespaces · 20 $output), assembled once and cached, and returned from $output. An importing generator gets it under its import handle (e.g. root.ms365); on this page call root.getMs365Api() — same object. Validation

Every module ships a self-contained validation suite (no network — every token/Graph endpoint is mocked, so the suites run instantly in any browser). Append a suite name to this page's URL to run it: ?test=oauth2 · ?test=tenant · ?test=graph · ?test=error · ?test=mailbox · ?test=email · ?test=calendar · ?test=files · ?test=file-transfer · ?test=file-perms · ?test=tasks · ?test=tasks-update · ?test=health · ?test=scoped · ?test=consumer — 178 tests across 15 suites, all green. The consumer suite is the import contract: it exercises the whole API headlessly with an injected fetch and injected async storage, no DOM, and no window.__m365 — proving construction is side-effect-free, configure() round-trips, a generic Graph call works, a 401 triggers refresh-and-retry, the relay redirect is shared and its message is accepted cross-origin, and $output is the API object.

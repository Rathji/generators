The display-card standard for Rathji's projects.

Every card on rathjis-generators currently shows only a simple emoji icon as its graphic. This page defines what a beautiful display card must look like, gives the rathjis-generators AI helper a copyable template, a reproducible detection method for finding icon-only cards, and a live audit that tracks the upgrade.

The Standard

What makes a card a display card

The old cards show a small emoji tile. An upgraded card leads with a real banner graphic — a hosted image — so the project reads at a glance, with the same title, description, tags and link the card already has.

FieldRequired?Purpose
imageYES — the whole pointHosted banner graphic for the card (generator's own $meta.image, or a generated one). Without it, the card is icon-only.
iconkeptEmoji fallback — shows only if the image is missing or fails to load.
titleyesProject name.
descyesOne-line description.
urlyesLink to the generator.
tagsyesFilter chips.
badgeoptionale.g. "hub", "vgn", "18+" pill in the top-right corner.
coloroptionalAccent colour per category — the card inherits it from the section automatically.

One field separates upgraded from not: image. Everything else is already in the card data today.

The Method

How to detect icon-only cards

No visual guessing — the card data lives in rathjis-generators' index.html as the PROJECTS object. The audit reads it straight from the public API and classifies every card by whether its entry has an image field.

  1. Fetch the live source. https://perchance.org/api/getGeneratorHtml?generatorName=rathjis-generators returns the current index.html.
  2. Extract PROJECTS. Grab the object literal that starts at const PROJECTS and ends just before const CAT_META.
  3. Classify each card. A card is ICON-ONLY when its entry has no image (and no img) field — its graphic is just the emoji icon. A card is UPGRADED when image is a non-empty string.
  4. Plan each upgrade. For every icon-only card, extract the generator slug from its url and check https://perchance.org/api/getGeneratorStats?names=<slug>. If data[0].metaData.image exists, reuse it as the card's image — if not, a new graphic must be generated.

# Theme Depot

A browser tool that pulls Obsidian community themes from the **Obsidian Hub** (`publish.obsidian.md/hub`)
and lets you browse, live-preview, and grab them for use in your own generators.

## How it works

- **Catalog**: fetched from the official community theme store
  (`https://raw.githubusercontent.com/obsidianmd/obsidian-releases/master/community-css-themes.json`,
  ~730 themes) — this is the same machine-readable list the hub's theme-store guide points at, and it
  carries each theme's `repo`, `modes`, `screenshot`, and `legacy` flags. Cached in localStorage for a day.
- **Hub enrichment**: the hub vault's `🗂️ Themes.md` index is fetched once to know which themes are
  documented in the hub and get their page URLs. When you open a theme, its hub page is fetched on
  demand to extract the description (and cross-check author/modes).
- **CSS**: `https://raw.githubusercontent.com/{repo}/HEAD/theme.css` (the theme-store convention) with
  a couple of fallback name variants for legacy themes. Relative `url()`/`@import` references in the CSS
  are rewritten to absolute against the stylesheet's directory so backgrounds/fonts resolve.
- **Preview**: a fake Obsidian workspace (ribbon, file explorer, note in reading mode with headings,
  code, tables, callouts, task lists, tags, properties) is rendered in an iframe. A minimal
  "Obsidian default" base stylesheet (`src/obsidian-base.js`) is injected first so themes that only
  override some CSS variables still look right; the theme's own CSS comes after and wins. The body gets
  `theme-dark`/`theme-light` like real Obsidian, so the Dark/Light toggle is just a class swap.

## Files

- `main.pjs` — config ($meta, kv-plugin import for favorites)
- `index.html` — UI shell (no logic; all code lives in `src/`)
- `src/app.js` — app controller: catalog rendering, search/filter/sort, category slicer, favorites
  (kv-plugin, stored in the `themeDepo` folder keyed by theme name), detail view, copy/download/embed
  actions
- `src/data.js` — data layer: fetching + parsing the store JSON, hub index, and hub theme pages;
  also `CATEGORIES` / `STRUCTURAL_CATEGORIES` (keyword-classified style/palette categories plus
  legacy & hub-documented flags), `classifyTheme()`, and the canonical quality/rank algorithm
  (`computeQuality()` + `computeRanks()`)
- `src/admin.js` — admin panel: runs the `src/tools/` scripts in-browser (via the
  `src/tools/SCRIPTS.json` manifest) and shows the JSON they produce to copy back into the `src/` file
- `src/preview.js` — builds the themed Obsidian iframe document
- `src/obsidian-base.js` — the Obsidian-default base CSS injected under every theme
- `src/style.css` — the depot UI's own styling
- `src/categories.json` — precomputed per-theme categories (generated by `src/tools/categorize.js`;
  the app fetches and overlays this at load for complete slicer data)
- `src/tools/categorize.js` — the bulk categorization script: fetches every hub theme description and
  writes `src/categories.json`
- `src/tools/CATEGORIZE.md` — the categorization process: how to run the script, when to re-run it,
  and how to add categories
- `src/tools/SCRIPTS.json` — manifest of runnable scripts for the Admin panel: add an entry here for
  any new `src/tools/` script (each must export an async `main(opts)` accepting `{limit}` and
  returning the produced JSON as `result.json`)
- `src/quality.json` — precomputed per-theme quality signals and sub-rank `[stars, lastCommitDays, docRichness, rank]`
  (generated by `src/tools/quality.js`; the app fetches and overlays this at load for instant scores)
- `src/tools/quality.js` — the bulk quality-enrichment script: GitHub stars + last-commit per theme
  (via shields.io) plus hub/docs data, then scores via `computeQuality()` and writes `src/quality.json`
- `src/tools/QUALITY.md` — the quality pipeline: the scoring algorithm, sources, and how to re-run it

## Categories / slicer

The catalog is sliced by category chips in the top bar. Categories are derived per-theme by
`classifyTheme()` in `src/data.js`:

- **Style/palette** (keyword-matched against name + repo basename + hub description, from the
  `CATEGORIES` list): Minimal, Colorful, Gruvbox, Dracula, Catppuccin, Tokyo Night, Nord, Solarized,
  Ayu, Neon / Synthwave, Nature, Retro / CRT, Anime.
- **Structural** (`STRUCTURAL_CATEGORIES`): Legacy, Hub-documented.

Categories are **precomputed for the whole catalog** by the bulk script
(`src/tools/categorize.js`, see `src/tools/CATEGORIZE.md`) into `src/categories.json`, which the
app fetches and overlays at load. Chips only render for categories with ≥ 2 members. A slice is
single-select and AND-combines with search, the dark/light mode filter, and the favorites filter.
If a theme is missing from `categories.json`, the app falls back to lazy keyword classification
of the static fields.

## Quality

Each theme gets a 0–100 quality score with a letter grade (A–D), computed by `computeQuality()` in
`src/data.js` — a weighted blend of five signals:

| Signal        | Weight | Source |
|---------------|--------|--------|
| Popularity    | 40%    | GitHub stars (log-scaled), via shields.io |
| Maintenance   | 25%    | Last-commit age (≤3 months full, decays), via shields.io |
| Completeness  | 15%    | Both light+dark modes & not legacy (store) |
| Documentation | 10%    | Hub page + description richness (hub) |
| Polish        | 10%    | Has a screenshot (store) |

The GitHub signals can't be fetched at runtime for 700+ repos (GitHub API: 60 req/hr unauth), so
`src/tools/quality.js` precomputes `[stars, lastCommitDays, docRichness, rank]` for the whole catalog
once (see `src/tools/QUALITY.md`) into `src/quality.json`, which the app overlays at load. Cards show
a sub-ranked grade badge (the best-scoring theme in each letter grade is `A.1`, next `A.2`, …; ties
break by stars then name — see `computeRanks()` in `src/data.js`, the canonical ranking used at
runtime and persisted in the file); the detail view shows the rank, score, stars, last update, and
per-signal bars. The default view sorts by ranking; the sort toggle cycles ranking → name → author.

## Curation (top 25%)

The catalog is curated by `curateCatalog()` in `src/data.js`: after ranks are computed, the bottom
`1 − KEEP_FRACTION` (75%) of the catalog is **eliminated** from the visible listing, and the letter
grades of the kept set are **re-scaled to distribute evenly** — the kept 25% is split into equal bins
across `GRADE_BINS` (A/B/C/D), so each grade holds ~25% of the kept set, then re-sub-ranked A.1/A.2/…
within each new grade. Dropped themes are flagged `curated: "dropped"` with their full-catalog rank
kept as `origRank`, and the app's **"Download removed (n)"** button (in the stats bar, next to the
sort toggle) exports them all as a JSON file (`theme-depot-removed-themes.json`) with their metadata,
source, and original rank/score — so nothing is lost, just moved out of the curated view. The cut uses
the same ordering as `computeRanks()` (score, then stars, then name). Tune `KEEP_FRACTION` /
`GRADE_BINS` in `src/data.js` to change the split or the re-scaled grade distribution.

## Backup (export / import)

Your favorites (stored in the kv `themeDepo` folder, keyed by theme name) can be backed up and
restored from the always-visible buttons in the stats bar above the catalog:

- **Export JSON** — lossless backup: `{format: "theme-depot-vault", version, exportedAt,
  favorites: [...]}` with each favorite's metadata (author, repo/source URL, modes, categories,
  rank, score, stars, screenshot) filled in from the live catalog. Saved as
  `theme-depot-favorites-YYYY-MM-DD.json`. Shows an error if the vault is empty.
- **Export Markdown** — human-readable and round-trippable: one `## <name>` section per favorite
  with `- **Author:** / **Source:** / **Modes:** / **Categories:** / **Rank:**` lines.
  Saved as `theme-depot-favorites-YYYY-MM-DD.md`.
- **Import…** — accepts either format (detected by extension, then content sniffing). JSON accepts
  a bare array, `{favorites:[...]}`, `{cards:[...]}` or `{themes:[...]}`; Markdown is parsed by
  `parseVaultMarkdown()` (headings + bold-key bullets), matching the export exactly so exports
  round-trip. Names already favorited are skipped and counted; new ones are persisted via kv and
  the grid re-renders. Feedback (including errors) appears in the `vaultMsg` status line.

Logic lives in `src/app.js` (`exportVaultJson`, `exportVaultMarkdown`, `parseVaultMarkdown`,
`importVaultFile`, `showVaultMsg`). The admin panel's Import/Export section points here.

## Admin panel

The gear/`Admin` button in the top bar (or the `#admin` URL hash, or `Ctrl/Cmd+Shift+A`) opens a
read-only admin panel. It lists every script in `src/tools/SCRIPTS.json` (currently the quality/rank
and categorize bulk scripts) with a **Run** button and an optional theme `limit` (0 = full catalog).
Running fetches the script, imports it as a data-URL module, and calls its `main({limit})` in the
browser — the same pipeline as the documented console workflow — streaming progress into a log and
showing the produced JSON in a copyable textarea. The JSON is **not** saved automatically: paste it
into the matching `src/` file (e.g. `src/quality.json`) in the editor. Full runs re-fetch the live
data and take 1–3 minutes; use a limit (e.g. 50) for a quick test. Import/export is a stub for now.

## Notes

- The hub access base URL (`publish-01.obsidian.md/access/e25082da…`) is the Obsidian Publish content
  endpoint for the hub; it's stable and allows CORS.
- `github.com/…/raw/…` redirects are blocked by CORS in browsers — always use `raw.githubusercontent.com`.
- Theme CSS is fetched by the user's browser directly (raw.githubusercontent allows CORS). Screenshots
  are `<img loading="lazy">` thumbs served from the same host.
- shields.io badge JSON (`img.shields.io/github/stars/…,json`) is CORS-enabled and has no meaningful
  rate limit, which is why it's used for the per-theme GitHub stats instead of the GitHub API.

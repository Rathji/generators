# plugin-doctor

A Perchance plugin standards auditor. Point it at any plugin (by name/link, or pasted source) and it runs a checklist against Perchance best practices **plus the user's own custom standards**, then produces a graded report (A–F) with copyable/downloadable AI-helper fix prompts and an embeddable self-check.

Uses the **rathji-template** visual style (dark navy `#0a0e17`, violet→cyan gradients, fixed blur nav, settings gear → theme/accent/size/motion persisted in localStorage, toasts, modals, code blocks).

## Files
- `main.pjs` — `$meta` (title/desc/tags/image/header) + `superFetch = {import:super-fetch-plugin}` import + a small `pluginDoctor` config list.
- `index.html` — the entire app: rathji framework CSS/JS (nav, settings, toasts, modals) + plugin-doctor engine (checks, custom-standards manager, grading, reports, embed).

## Architecture (index.html)
- **Built-in checks**: `makeChecks()` (index.html) returns ~24 checks grouped into categories (Structure & $meta, List structure & DSL, Code quality, Security, Docs & UX, HTML & layout) with `{st:"pass"|"fail"|"warn"|"na", det}` evaluator functions. Levels: required (3 pts) / recommended (1 pt) / info (unscored). Required-failure caps grade at C.
- **Custom standards**: `customChecks` array (localStorage key `pluginDoctorStandards`), each `{label, category, level, target(pjs|html|both), mode(regex_present|regex_absent|regex_count|js), pattern, flags, minCount, js, waiveIf, hint, enabled}`. `compileCustom()` turns one into a check; `parseImportText()` handles JSON import (object with `checks` array, or bare array) for Replace/Append; `exportStandardsJson()` exports. Form editor in `#ckModal`; JSON import in `#importModal` (`?std=` URL param also imports).
- **Audit flow**: `auditName(name)` fetches `getGeneratorsAndDependencies` (pjs + imports) and `getGeneratorHtml` (html) via `superFetch`; `auditTarget(st)` runs all checks against a target; `gradeReport(st)` scores/grades; `runAudits(names)` renders cards. Paste mode: `runPasteAudit()` (no network).
- **Outputs**: `renderCard(st)` (badge, score bar, category chips, expandable check rows, per-issue 🎯 fix prompts via `buildOneFixPrompt`), `copyReport`/`gradeReport` for .md, `buildFixPrompt(st)` full AI-helper prompt. Multi-plugin bar with Copy all / Download all / Download fix prompts.
- **Embed/self-check**: `?embed=1` shows only the compact audit row; `?g=NAME` auto-audits. `window.pluginDoctor` API (`check`, `auditName`, `auditTarget`, `gradeReport`, `copyReport`, `buildFixPrompt`, `buildOneFixPrompt`, `allChecks`) + postMessage handler (`plugin-doctor-check` → `plugin-doctor-check-result`). `SELF_SNIPPET` / `SELF_AI_INSTRUCTIONS` are the copy-paste embed for other plugins' AI helpers ("Check standards" link) — resolves plugin-doctor's publicId at runtime via `getGeneratorStats` (needs this generator SAVED and public).
- **Generator → plugin converter** (`#convertSection`): enter any generator name/link → `analyzeGenerator(name)` fetches its main.pjs + index.html via `superFetch`, inventories top-level names/imports/root refs/window refs/hardcoded names/html stats, and `recommendShape(st)` picks a shape (CODE / DATA·EMBED / BOTH) with reasons + blockers. `buildConvertPrompt(st)` emits a paste-ready prompt (embedded playbook `CONVERT_PLAYBOOK` + inventory + source excerpts) for the AI helper; `inventoryReport(st)` is the inventory text. Buttons copy/download that prompt, or `generatePluginDraft(st)` streams two AI drafts (plugin main.pjs + demo index.html) via `root.generateText` into `#convertDraftFiles` with Copy/Download per file. Exposes `analyzeGenerator`, `buildConvertPrompt`, `inventoryReport`, `recommendShape` on `window.pluginDoctor`.

## Notes / gotchas
- **DSL escaping**: literal `{`/`[` in index.html text nodes and non-event attribute placeholders must be backslash-escaped (`\{`, `\[`) or the Perchance engine tries to parse them as curly/square blocks (this caused `$output.toString is not a function` and "invalid escape sequence" errors during early dev). Content inside `<script>`/`<style>` tags is NOT parsed — only text nodes and non-event attributes.
- **`{import:...}` inside BACKTICK template literals is still scanned** by the engine's import extractor (it sees past quotes). The converter playbook therefore writes the literal via `IMP(n) => "{import:" + n + "}"` and interpolates `IMP("...")` inside double-quoted strings — double quotes ARE safe (proven). Never put a literal `{import:x}` in a backtick string.
- **ai-text-plugin output cap**: `generateText` cuts responses at roughly ~1000 tokens (~3KB) regardless of instruction. The AI draft prompts therefore enforce a HARD BUDGET rule (skip data lists → placeholder comment, spend budget on complete code, end exactly with `$output = [myPluginMakeApi()]`) and use `startWith` (`$meta` / `<style>`) so the two sequential calls can't collide via prefix-cache. A truncation heuristic flags dangling endings. Generation requires `root.generateText` (ai-text-plugin) — note importing ai-text-plugin shows an ad to non-logged-in users.
- All code lives in index.html; main.pjs is only config (imports + `pluginDoctor` list). No build step.
- Self-check embed requires the generator to be saved/public (snippet resolves its live URL at runtime).
